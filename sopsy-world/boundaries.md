# Boundaries of this world

## What this world covers

Where code, tests, tooling and workflow of sopsy live, which conventions apply and how the state is derived. Every statement has an address in the coverage map of `world.md`. The hard rules are in `CLAUDE.md`, not here.

## What this world does not cover

- **Product decisions:** what sopsy should and should not do. Source: `docs/design.md` and the specs in `openspec/specs/`; the human decides.
- **Mission:** current work and its order. Source: open GitHub issues and `openspec/changes/`; always query live.
- **Release approval:** pushing a tag publishes a release; only the human approves it.
- **Numbers and state:** files, tests, open issues, versions. Always derive them with the commands of the coverage map, never from these files.

## When no source answers

Report the gap and ask the human. Do not invent a plausible answer.
